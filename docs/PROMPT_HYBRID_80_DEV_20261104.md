# QASPER 开发集 80 题提示词对照

## 测试范围

此前 18 题是小规模提示词诊断，不是 QASPER 的全部题目。这次从 QASPER dev 固定抽取 80 道单论文问题：抽取题 30、概括题 20、是非题 18、所有参考标注均为不可回答的题 12。问题来自 64 篇已建库论文，与之前的 200 题和 60 题没有问题 ID 重叠；论文此前已使用过，不能称为新论文盲测。按题型分层且刻意提高是非和不可回答题占比，不能将结果视作数据集自然分布的平均表现。

每题使用同一现成 Milvus 索引，先做 dense + BM25 混合检索，召回 20 条，使用 BGE reranker 重排至 Top-5；固定证据后，分别交给原正式提示词和精炼候选提示词。两版使用本地 Qwen3-4B、相同证据和生成设置，交替调用先后顺序，标准答案不放入模型输入。80 题两版均完成，80/80 对的输入片段哈希一致。所有调用在本机完成，未调用付费模型 API。

测试调用了问答图的准备、生成和解析节点，未覆盖 PDF 解析、HTTP、UI、流式输出、多轮历史或线上搜索。索引来自 QASPER 的结构化论文文本。

## 筛查结果

### 四种题型的答案匹配

将两版**原始答案**与每题所有参考答案计算 QASPER 官方脚本的词级 Answer F1，逐题取最高参考分数，再按本次样本的题型求平均。这里没有把模型的解释改写成标准答案，也没有将自然语言拒答改写为官方的 `Unanswerable`。数字只衡量用词重合，不等于事实正确率。

| 题型 | 题数 | 原提示词 Answer F1 | 精炼候选 Answer F1 |
| --- | ---: | ---: | ---: |
| 抽取题 | 30 | 0.261 | 0.524 |
| 概括题 | 20 | 0.246 | 0.264 |
| 是非题 | 18 | 0.009 | 0.556 |
| 标注不可回答题 | 12 | 0.000 | 0.000 |
| 全部 80 题，按本次分层样本加权 | 80 | 0.161 | 0.388 |

抽取题的提升主要来自候选答案更精炼。例如“收集了多少条推文”，原答案和候选答案都依据同一段文本正确说出 700；候选只输出 `700`，因此词级分数为 1，原答案因为包含额外解释得分明显较低。另一题问数据集语言，候选只回答 `English`，而原答案错误地把回译时临时使用的德语、法语、希腊语也当作数据集语言：此题是候选的实质改进。

概括题的均值接近，但两版有不同错误。例如“哪种算法表现最好”，原答案正确说出最佳人气方法与最佳相似度方法组成的混合方法，候选只输出论文解析占位符 `INLINEFORM7`，用户无法据此理解答案。另一题问对话平均轮数，给定片段含 8,533 轮和 1,900 段对话，原答案算出约 4.49；候选却称文本未直接提供并拒答。相反，部分题的候选缩短答案后词面分数上升，仍需逐题检查是否遗漏必要信息。

是非题的词级分数尤其受格式影响：候选直接输出 `Yes` 或 `No`，与相同参考词时得 1；原版常用完整句子，纵使意思相同，词级分数也可能非常低。标注不可回答题的官方参考文字是 `Unanswerable`，两版自然语言拒答均不会与这个词重合，所以两版原始答案的这一项均为零；不能据此说两版都没有拒答能力。

以上具体例子是对所给检索片段的 AI 初步核对，并未将全部 80 题逐条进行独立人工事实判断。

### 检索与回答行为

| 观察项 | 原正式提示词 | 精炼候选提示词 |
| --- | ---: | ---: |
| 成功完成 | 80/80 | 80/80 |
| 18 道是非题，回答开头明确 Yes/No | 6/18 | 18/18 |
| 有一致标注且回答开头明确 Yes/No 的是非题，与标注一致 | 3/6 | 7/15 |
| 12 道标注不可回答题，文本出现规则可识别的拒答表达 | 5/12 | 4/12 |

以上统计均是输出形式和标注一致性的筛查，不是经语义复核的正确率。是非题的标注有不同标注者意见不一致的情况；仅在参考标签一致且回答开头是明确 Yes/No 时统计一致性，分母因此不同，不能直接将 3/6 和 7/15 解释为谁的准确率更高。拒答识别基于字符串规则，可能漏判或误判；即便模型表达了不确定，也可能附带未经支持的推断。

对 68 道按标注有答案的题，63 道能将参考证据映射到论文结构化段落。用“检索 Top-5 片段与任一参考段落去重词覆盖至少 80%”作为粗略代理，其中 40/63 达标；另 5 道因参考段落未能映射，不进入分母。两版使用相同片段，所以这项检索筛查对两版相同。该代理会漏掉同义表达或其他有效证据，不代表经过人工审定的证据召回率。

12 道标注不可回答题中，有些标签与当前提供的文本不一致。例如问题询问论文如何展示方法的适用性，论文摘要直接写出“为名画生成莎士比亚风格的散文”，两版均据此作答；因此不能仅因与不可回答标签不同就认定模型作答错误。相反，另一题询问实验是否只使用英语：候选提示词回答 No，而其引用片段只说实验使用 Freebase 和 WordNet，没有说明实验数据的语言，因此该引用不足以支持“No”。原提示词对同一题也推测实验使用其他语言，引用同样不够支持。上述判断是基于本次提供片段的 AI 初步复核，不是独立人工验收。

原提示词对于 18 道是非题更常给出解释或表达不确定，候选则全部直接给出 Yes/No。后者更符合形式要求，却不能证明判断可靠；12 道标注不可回答题上也没有观察到更好的拒答信号。不能仅因回答更简短、引用字段存在或匹配标签就认定候选更好。

后续使用决定（2026-11-04）：应用户要求，已将本报告的精炼候选提示词设为正式 `RAG_QA_PROMPT`。这是在了解上述局限后作出的产品选型，不改变本次评测结果。生产提示词与冻结候选的 SHA-256 一致；普通和流式问答的准备节点、JSON 回答与引用解析已通过本地烟测。历史评测使用的两版提示词原文保存在本机运行目录的 `prompts.json`。

本次混合检索与重排耗时中位数约 12.39 秒/题；两版生成耗时中位数分别约 2.34 秒和 1.54 秒/次。这些是本机本批次测量，不是并发性能或端到端响应时间。

## 文件与限制

冻结样本、参考答案、逐题检索片段、两版原始输出和输入哈希保存在 `evaluation/runs/prompt_hybrid_80_dev_20261104/`；`manifest.json` 与 `runtime.json` 保存测试配置，`screening/` 保存规则筛查结果。运行产物为本机文件，不默认纳入 Git。

本实验明确指定混合检索和重排；实验执行当时，项目仍默认 dense 且重排关闭，本实验本身没有改变生产检索配置。后续版本已将代码、Compose 和示例环境默认改为混合检索＋BGE 重排；离线运行需配置容器内的重排模型路径，见 [部署说明](REPRODUCIBLE_DEPLOYMENT.md)。80 题比 18 题更有诊断价值，但仍需更多新论文题目、证据充分性和事实正确性复核，才能更有把握地比较方案；提示词也不能保证完全杜绝错误。
