## 验收期间发现并修复的问题

1. “证据不足”案例的引用在 MySQL JSON 往返后，仅有一条检索分数末位发生浮点精度变化。原验收脚本要求 JSON 字段逐位相等，因此误报失败。现在对检索分数使用数值容差，其余引用字段仍逐项严格比较。五道已保存答案重新校验全部通过，没有重复调用模型。
2. 前两条成功的多轮对话轨迹各有一个 LangGraph 子节点被标为 `GeneratorExit`：调用方收到最终答案后提前关闭图迭代器。现在先耗尽图流，再发最终答案，并增加相应回归测试。修复后的新增真实问答轨迹 ID 为 `01a19bf5-2fbd-7f71-a029-1702e20bb3fb`，包含 23 个节点、22 个关联子节点、0 个错误，并可看到 `ProviderChatModel` 与 `ScopedPaperRetriever`。旧轨迹保留原有标红记录，不能据此声称旧运行从未报错。
