# QASPER 单项提示词优化与扩展回归（2026-11-13）

本轮测试一项生成改动。候选提示词要求模型先确认问题的对象、范围和处理阶段，再选择直接支持结论的原句。它也明确规定肯定和否定都需要证据，证据不足时用问题的语言说明无法确定并返回空引用。

## 评测设计

| 题组 | 题数 | 证据来源 |
| --- | ---: | --- |
| 固定试跑 | 30 | 重放 11 月 8 日诊断保存的系统检索片段 |
| 固定开发集 | 200 | 沿用历史 200 题 ID，按官方章节结构重建 151 篇论文，共 5,256 个片段 |
| 留出集 | 50 | 从官方 test 划分抽取，每篇取一题，共 50 篇论文和 1,708 个片段 |

开发集与试跑没有题目 ID 重叠。留出集在试跑前固定，随机种子为 20261113，并排除本地历史评测记录中已识别的 30 篇 test 论文。两套正式评测索引使用独立的 Milvus 集合。为缩短建库和重排时间，在项目内建立独立 CUDA 环境，用原有 BGE-M3 和 BGE 重排权重执行真实检索。

每题把同一批冻结片段交给两版提示词。生成走当前 AnswerGraph 的准备、生成和答案解析节点，使用本机 Qwen3-4B，temperature 为 0，上限为 2,048 个输出 token。交替执行两版的先后顺序。保留实际输入、原始回答、引用、用量和耗时。评测模型调用全部在本机完成。

答案与引用证据 F1 按官方算法计算，保留回答原文。拒答计数使用现有规则识别空引用的缺少信息表达，单独报告所有标注均为不可回答的题目，以及有可回答标注的题目。Top-5 命中按现有正文段落映射，统计至少命中一个非图表标注证据的题目。QASPER 结构化文本没有图表单元格。耗时以保存的检索耗时与同题生成耗时相加，覆盖评测调用路径。

自动拒答规则在开发集将候选版计为 3 道，漏掉了一句“平均标题长度无法根据所给片段确定”。对所有官方一致标为不可回答的题重新核查输出后，开发集两版各有 4 道明确拒答，留出集原版 2 道、候选版 1 道。这里统计的是回答有没有明确承认缺少信息。官方词汇 F1 仍按原文比较，包含 `Unanswerable` 表达差异。

## 代表案例与采用决定

- 开发题 `c34e80fb` 问 Wikipedia 方法能否用于其他领域。原版回答 Yes，候选版指出片段只描述 Wikipedia，无法确定能否推广。
- 开发题 `4d7ff4e5` 问本文采用何种表示学习架构。原版明确拒答，候选版把原文归属给 BIBREF12 的 PV-DM 和 PV-DBOW 当成了本文方案。
- 开发题 `2eb9280d` 问数据集大小。原版提取出 13,939，候选版采用引言里的近似值 14,000。两处数字都见于原文，候选回答丢失了更精确的规模。
- 开发题 `9cf070d6` 两版都答出 1,500 句。候选版用了完整句子，词汇 F1 从 1.00 降到 0.29，这一变化属于表达长度差异。
- 留出题 `5138121b` 问翻译表现提高了多少。原版明确指出片段缺少定量幅度，候选版只回答“显著提高”，漏掉了问题要求的增幅及无法核实的说明。

保留原版为默认提示词。候选版改善了回译语言错例和抽取式 F1，开发集整体收益没有复现，留出集答案 F1 下降 0.0308，明确拒答少 1 道。留出集只有 3 道标注一致的不可回答题，拒答结果应结合上述逐题案例理解。
