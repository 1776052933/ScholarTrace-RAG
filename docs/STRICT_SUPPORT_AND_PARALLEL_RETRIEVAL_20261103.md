# 多论文并发检索与保守拒答（2026-11-03）

## 正式问答路径

正式 `RAGReader` 默认使用均衡取证：对 2～5 篇选定论文分别保留证据，先计算一次问题向量，再将 Milvus 的逐篇查询限制在最多 3 路并发。检索结果按用户选文顺序合并，重排仍在主线程顺序完成。证据补检对缺证据论文也使用同一批量接口。直接构造 `PaperQA` 的旧评测入口继续保留原有覆盖策略，避免改变已归档基线。

2026-11-03 的实验版本在回答生成后、展示前默认执行了支持性核验：

1. 检查引用 ID 均来自本轮提供的片段；跨论文回答必须引用每篇选定论文。
2. 把问题、拟回答和被引用片段交给当前配置的大模型再核验一次。核验器必须逐字摘出每个被引用片段的支持引句，且判为 `supported`。
3. 引句必须实际出现在对应片段；回答中的阿拉伯数字必须能在引句中找到。任何不确定、引用缺失、核验响应无效或核验服务故障都返回无引用、置信度 0 的拒答。

该实验通过 `RAG_STRICT_SUPPORT_ENABLED=true` 启用。2026-11-04 评测发现过度拒答，现已改为默认 `false`。启用时，严格模式的 SSE 保留进度消息，并把答案文字缓冲到核验结束后一次发送；它会增加一次模型调用与等待时间，也可能拒绝本来可回答的问题。

## 检查结果

- 无密钥 CI 范围内 **142 项测试通过**，新增测试覆盖并发路径的单次嵌入、顺序合并、串行重排，以及缺引用、跨论文引用不全、数字不匹配、核验不确定和流式草稿不泄漏。核验提示词补入多轮追问的指代消解问题后，相关 12 项关键测试再次通过。
- 在隔离 Compose 项目中，使用已有两篇测试论文、本地 BGE-M3 和真实 Milvus：观测到同时有 2 个逐篇查询；每篇返回 3 个片段。检索阶段三次预热对照的中位耗时为逐篇串行 **0.3418 秒**、复用一次向量并两路查询 **0.1568 秒**。这次测试未启用 reranker，数字只针对检索阶段，不能外推整轮问答。
- 同一环境中的 FastAPI 问答与会话 SSE 使用假模型验收：支持性路径保留两篇引用；核验返回 `uncertain` 时持久化和界面展示的都是无引用拒答，未展示未核验的草稿。该验收没有调用外部模型 API。

**边界：**模型核验器可能误判，PDF 解析得到的片段也可能与原页不一致，因此这套门控能降低误答风险，不能数学上保证零错误。此前引句门控实验出现过过度拒答；本轮尚未对真实 DeepSeek 回答跑新的逐题人工正确率、引用支持率及拒答率对照，不能宣称这些质量指标已改善。正式质量结论需要在固定已复核题集上比较“错误作答率”和“可回答却拒答率”，并核对原 PDF。

本机原始 API 验收记录位于 `data/repro_acceptance_20261102/runtime/strict_evidence_acceptance_20261103.json`，被 Git 忽略。
