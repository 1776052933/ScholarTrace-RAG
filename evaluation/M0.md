# M0 固定基线评测

这两个入口在升级前直接调用现有 BGE-M3 / Chroma / RAG 代码，结果写入被 Git 忽略的 `evaluation/runs/`。M0 只建立可重复的对照口径；M6 再加人工审查、PDF 页码集和更完整的质量评估。

## 前置条件

- 在项目根目录运行，安装 `evaluation/requirements.txt`。
- `data/benchmarks/` 已有 LitSearch 与 QASPER；下载和校验方法见 `docs/DATASETS.md`。
- 运行前确认模型 `BAAI/bge-m3` 可加载；评测器发现现有代码回退到哈希向量时会报错。
- 只有 QASPER 完整问答需要 DeepSeek 密钥；`--retrieval-only` 和 LitSearch 固定语料检索不调用 DeepSeek。

## QASPER：单篇全文 RAG

先验证一题检索和指标：

```powershell
python -m evaluation.run_m0_qasper --split dev --limit 1 --seed 42 --retrieval-only
```

运行固定的 20 题问答样本（会产生模型 API 调用）：

```powershell
python -m evaluation.run_m0_qasper --split dev --limit 20 --seed 42 --top-k 5
```

中断后用相同参数与 `--run-dir evaluation/runs/你的运行目录 --resume` 续跑；续跑会核对代码、数据、模型和题目列表，再跳过已有逐题记录。

`--limit 0` 表示整份 split。问题抽样由 seed 固定，抽中后按论文分组，避免同一篇反复入库。评测用的是 QASPER 的结构化论文全文，按原项目清洗、1000 字符切块、200 字符重叠、BGE-M3 嵌入，再按论文 ID 做 Chroma Top-5 检索。问答调用现有 `RAGReader.ask`，不向模型提供标准答案或证据标注。

输出的 `evidence_recall_proxy` 以人工高亮证据为单位：每段金标准证据有至少 80% 的词出现在某个召回 chunk 中即算命中；多位标注员取最佳标注。无证据的不可回答问题不参与这个指标。`answer_token_f1_proxy` 是回答与人工参考答案的最大词级 F1；现有中文问答提示词可能生成中文回答，和英文参考答案词面不一致，因此它只能用作诊断，不能代表语义正确率或官方 QASPER 分数。`has_citation` 只统计是否给出引用，不能证明引用支持答案。最终需人工核查代表性回答。

## LitSearch：固定语料 dense 检索

先验证 32 篇、2 个问题的流程：

```powershell
python -m evaluation.run_m0_litsearch --corpus-limit 32 --query-limit 2 --top-k 20
```

完整固定语料与全部问题：

```powershell
python -m evaluation.run_m0_litsearch --corpus-limit 0 --query-limit 0 --top-k 20 --run-dir evaluation/runs/m0_litsearch_full
```

中断后使用同一参数续跑：

```powershell
python -m evaluation.run_m0_litsearch --corpus-limit 0 --query-limit 0 --top-k 20 --run-dir evaluation/runs/m0_litsearch_full --resume
```

这里逐篇索引固定 `corpus_clean` 的**标题和摘要**，调用当前 BGE-M3 和 Chroma 做全库 dense Top-K，按官方 query 的 CorpusId 计算 Precision、Recall、Hit、MRR@5/10/20。该入口是可复现的固定语料检索基线，并不调用项目的实时 SearchAgent，也不等同于 LitSearch 官方榜单。前 N 篇的抽样语料可能不包含问题的正确论文，因此小样本指标只用于流程验证，不用于质量结论。完整 6.4 万篇在 CPU 上耗时较长，并会占用较多磁盘空间。

## 输出与对照规则

每次运行产生 `manifest.json`（代码指纹、数据哈希或修订、模型、参数、题目 ID）、`records/*.json`（原始输入、检索证据或论文、回答、指标和错误）、`summary.json`（宏平均、失败数、时间）、`chroma/`（本次索引）。LitSearch 另有 `index_state.json`，支持按批次续跑。运行目录不加入 Git；需要公开的报告可从逐题记录提取汇总，并移除不适合分发的原文。

比较 M1–M6 时固定 split、题目 ID、语料、Top-K 和评测脚本版本，分别报告论文发现、证据检索、问答三种任务。失败题单列，不从分母中悄悄删除。实时学术 API 搜索沿用 `evaluation.run_litsearch`，与固定语料结果分开展示。
